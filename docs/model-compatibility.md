# 공식 샘플 모델 호환성 기록

2026-09-22, macOS 26.6.2 arm64. 고정한 공식 SDK의 **10개 묶음·9개 캐릭터 계열**을 검사했다. Kei 기본/모음 모델은 다른 파라미터 구성이지만 같은 캐릭터 계열로 센다. 기획서는 알파에서 ‘서로 다른 모델 최소 10개’를 요구하며 제작자나 사용자 제작 여부를 제한하지 않는다. 현재 공식 샘플 검사와 양 OS 배포 앱·알파 실사용 검증은 구분한다.

## 수행한 검사

1. `docs/sdk-lock.json`의 공식 SDK ZIP SHA-256과 캐시의 모든 모델 원본 파일 바이트를 대조했다.
2. 제품 `ModelStore`로 폴더와 ZIP 각각 `inspect_source → read_import_asset → import → read_asset`을 실행했다. 총 20경로가 통과했고, 정제한 미리보기와 확정 후 자산이 바이트 단위로 일치했다. 검증 자산 164개를 검사 전용 폴더로 내보냈다.
3. 내보낸 자산을 실제 `CharacterRenderer`로 로드했다. 각 모델에서 5감정 요청·커서·음소거 한국어 샘플 재생/취소를 실행하며 Core 파라미터 유한성·실제 범위를 검사했다. 실제 GPU 출력에 불투명 픽셀이 있고 GL 오류가 없는지 확인했다. 생성한 각 모델의 화면도 브라우저에서 확인했다.
4. Wanko의 구형 ID를 수동 연결해 추적·표정 표시가 미지원에서 대체 동작으로 바뀌는지 확인했다. Rice에 없는 입 모양을 지원한다고 표시하지 않는지도 검사했다.

브라우저는 Codex In-app Browser(Chrome 152), CSS canvas 300×400, DPR 2, 30 FPS 설정이다. 각 모델을 약 2초 동안 검사한 결과이며 연기 자연스러움·장시간 안정성·네이티브 프레임 성능의 합격 판정은 아니다. [원본·출력 해시와 측정 요약](model-compatibility-2026-09-22.json)에 근거를 보관한다.

## 실제 기능 표시

아래는 저장된 사용자 매핑 없이 로드한 결과다. 모든 묶음에서 물리 자산이 연결됐고 런타임 경고·GL 오류는 없었다. ‘대체’는 음량 기반 입 개폐나 일부 파라미터 기반 표정처럼 제한된 표현이다.

| Haru | 42 | 지원 | 대체 | 대체 | 48 |

| Mao | 132 | 지원 | 지원 | 대체¹ | 55 |

¹ 이번 검사는 원본 Mao를 사용자 모델로 가져온 경우다. 기본 제공 Mao에는 별도의 앱 전용 MotionSync 설정을 연결하며 그 경로는 기존 PCM/브라우저 검사에서 확인했다.

² Rice에는 수직 고개·입·눈썹 파라미터가 없으므로 지원 표시는 모든 축/감정/몸짓의 지원을 의미하지 않는다. 넓은 원본 모델 canvas 때문에 초기 캐릭터가 작게 보이므로 모델별 표시 크기를 조절할 수 있다.

³ Wanko는 `PARAM_ANGLE_X/Y`, `PARAM_BODY_ANGLE_X`, `PARAM_BREATH`, `PARAM_MOUTH_FORM`을 수동 연결하면 고개 추적·표정이 대체 동작으로 표시된다. 눈동자 이동 파라미터는 없으므로 눈 추적까지 지원한다고 표시하지 않는다.

Ren은 Cubism 5.3 MOC의 오프스크린·신형 블렌드 경로를 사용한다. 이후 [실제 픽셀 비교](model-hit-testing.md)에서 CPU 클릭 판정에 신형 알파 합성을 반영했고, Ren 연속 재로딩 때 삭제된 framebuffer를 다시 사용하는 캐시도 수정했다. 희소 격자의 명확한 투명·불투명 영역은 일치했으나 경계 래스터 근사와 네이티브 클릭 통과 검증은 남았다.

## 자원 반환과 한계

실제 WebGL 생성/해제 API를 감싸 계수했다. 전체 검사에서 Buffer 1,405개, Framebuffer 17개, Program 242개, Shader 484개, Texture 30개가 생성됐고 모두 해제됐다. Ren 로드 중에는 Framebuffer 9개·Texture 10개가 유지됐고 다음 모델로 바꾸면 해당 모델에 필요한 수로 줄었다. 최종 추적 핸들은 모두 0이다. 이는 GPU 바이트나 전체 메모리 누수, 프레임별 할당 비용이 충분히 작다는 증명이 아니다.

검사기는 실제 앱의 저장소·기억·설정을 사용하지 않는다. 추가 모델은 배포 자산에 포함하지 않았고 결과 페이지도 production Vite 입력에서 제외된다. 네이티브 파일 선택·드롭·권한, 두 OS 배포 앱의 시청각 품질과 모델 호환성, 사용자 알파는 미검증으로 유지한다. macOS 클릭 통과는 이후 사용자 직접 확인 결과를 통합 검증 기록에 반영했다.

## 재현

```sh
npm run assets:setup
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run test:compatibility
npm run dev
```

`http://127.0.0.1:1420/tests/browser/model-compatibility.html`에서 **모든 샘플 검사**를 누른다. `.cache/model-compatibility/catalog.json`은 이번 가져오기 검사 결과이며 원본·검사 ZIP·출력 자산 해시와 검사 경고를 담는다. 검사기의 추가와 CI 작업 정의는 Windows에서 실행됐다는 뜻이 아니다.
