# MVP 검증 기록

2026-09-22 최초 기록. 근거는 루트 기획서와 AGENTS.md다. **코드 구현, 자동 검증, 두 OS 배포 앱 검증, 사용자 알파는 서로 다른 단계**이며 하나의 완료로 합치지 않는다. 아래 미검증 항목은 통과한 것으로 간주하지 않는다. 렌더러·Tauri·설정 화면은 연결했으며, 아래 자동 검증과 브라우저 확인을 수행했다. 네이티브 실기 검증은 아직 완료되지 않았다.

## 실제 브라우저 반복 검사

개발용 `tests/browser/model-soak.html`에서 공식 Mao/Haru/Kei를 50회 교체했다. 실제 Core·WebGL2·MotionSync·Web Audio API를 감싸 생성/해제를 세며 원래 호출을 실행한다. 최종 결과는 [측정 요약 JSON](browser-model-soak-2026-09-22.json)에 보관했다.

- 26.119초 동안 기본 50회 교체, 지연된 물리 자산 요청 중 교체, `WEBGL_lose_context` 손실·복구를 완료했다. 최종 오류 배열은 비어 있고 복구 후 실제 GPU draw가 재개됐다.
- 최종 해제 후 Core Model/Moc·Texture·Buffer·Framebuffer·Program·Shader의 추적 핸들은 모두 0, MotionSync 분석기·예약 rAF도 0, AudioContext는 closed다. 반복 중 각 모델의 자원 수가 증가하지 않는지도 검사했다.
- Haru, CSS 360×500, DPR 2, Chrome 152 기반 브라우저, 각 2.2초 표본에서 30 설정은 30.02 FPS(간격 중간값 33.3ms/p95 50ms), 60 설정은 55.42 FPS(16.7ms/32.5ms)였다. 브라우저 rAF는 60Hz였고 최종 측정 중 Tauri debug 빌드를 병행했다. 안정된 60 FPS를 입증한 결과가 아니다.
- 정지 중 250ms 동안 draw/rAF 0, 재개 후 루프 1개를 확인했다. JS heap 단일 표본은 GC·SDK 전역을 포함하므로 메모리 누수 판단에 사용하지 않는다. 네이티브 프로세스 전체 RAM/GPU·전력·8시간 측정은 여전히 미실시다.

이 검사에서 미완료 모델의 Core 해제, GL별 셰이더 캐시 해제·재생성, MotionSync 부분 생성 실패 정리, rAF 예약 위상 보존을 보완했다. 그래픽 연결 손실 이벤트 직전/그리기 중 예외도 보완해 재검사했다. SDK 수정은 원본/수정 SHA를 고정한 `assets:setup` 패치로 재현한다.

## 실제 배포 앱 검증 절차

1. README의 정식 빌드 명령으로 생성한 macOS `.app`와 Windows 실행 파일을 사용한다. OS/버전/아키텍처, 기기, SDK, 모델, 음원, FPS, 표시 크기, AI 제공자/모델, 네트워크를 기록한다.
2. 다른 앱 편집창에 커서를 둔다. Ouento 시작 위치와 투명도/가장자리를 확인한다. 투명 여백 클릭이 편집창에 도달하는지, 캐릭터 드래그가 끊기지 않는지, 포커스가 바뀌는지 각각 확인한다. 항상 위 설정 on/off도 확인한다.
3. 창 밖 커서·화면 가장자리·음수 좌표로 이동한다. 배율이 다른 두 모니터 사이에서 창을 이동하고 좌표/크기/시선이 튀지 않는지 확인한다. 마우스 해제 후 클릭 통과 상태가 복구되는지 본다.
4. Mao 5감정 각각 → 평온 복귀를 확인한다. 눈 감은 표정으로 말하면서 커서를 옮긴다. 깜박임이 감정을 덮거나 입이 대기 모션과 충돌하지 않는지 확인한다. Haru로 바꿔 다른 매핑을 확인한다.
5. 고정 한국어 TTS 음원에서 무음 구간·일시정지·취소·긴 재생을 본다. 발화 중 사용자 마이크 시작/모델 교체를 수행하고 늦은 오디오/입 모양이 재시작하지 않는지 확인한다. Kei MotionSync 검증 후 Mao 전용 입 형태를 확인한다.
6. 합성 텍스트만 있는 테스트 창 A를 명시적으로 허용하고, 비공개 표시 B는 허용하지 않는다. A를 B로 가려도 캡처 결과에 B가 포함되지 않아야 한다. 자체 창·민감 앱·최소화·닫힌 창·PID 교체는 수집이 거부되어야 한다. 캡처 결과는 테스트 후 폐기한다.
7. 분석 버튼을 누른 직후 취소/새 직접 대화, 분석 및 TTS 대기 중 관찰 중지·선택 창 전환·권한 철회를 각각 수행한다. 재생 중 대상 창을 닫거나 권한을 철회했을 때 해당 관찰 발화만 멈추는지도 확인한다. 새 수집/전송/오래된 반응이 중지되고 직접 대화와 캐릭터 표시가 계속되는지 확인한다. 조용히 있기는 관찰 중지와 다른 상태로 표시되어야 한다.
8. 입력 중·수동 집중·회의 모드에서는 자동 반응이 쉬고 명시적 화면 분석은 동작하는지 확인한다. 음소거의 말풍선 동작도 확인한다. 합격·불합격·타인 합격·소유자 불명 장면과 질투 off/낮은 빈도 장면을 비교한다.
9. 화면 잠금·절전·해제·네트워크 끊기/복구·모니터 분리/연결을 각각 수행한다. 잠금 동안 관찰과 렌더가 멈추고 복귀 직후 큰 움직임/중복 발화/오래된 화면 재분석이 없는지 확인한다.
10. 잘못된 모델 ZIP과 정상 모델, 기능 부족 모델을 가져온다. 오류/대체 동작/미지원이 구분되는지, Core 검사를 통과하기 전 지원 확정이 표시되지 않는지 확인한다. 기억 저장 off/on, 수정/삭제/만료, 인격 유지/새 시작을 재실행까지 확인한다.
11. 동일 조건에서 대기·추적·발화·화면 분석·50회 모델 교체·8시간 실행을 측정한다. 실행 시간을 늘려 발견한 문제를 기록하며 시험 전 목표치를 성능 결과로 쓰지 않는다.

## 이번 통합에서 수정한 문제

- 수동 화면 분석은 자동 관찰의 입력·침묵 제한과 구분한다. 캡처 준비 전에 취소 세대를 고정하고, 응답에는 원래 네이티브 대상을 연결해 TTS 대기·완료·재생 중 창 변경과 권한 철회를 검사한다. 이전 발화의 늦은 취소 이벤트는 같은 ID의 관찰만 중지한다. 합성 HTTP/OS 자료와 UI/오디오 회귀로 검증했으며 실제 권한 철회는 실기 검증이 남았다.
- 전역 표시 크기가 고정 창 안의 모델만 확대하던 것을 네이티브 창 크기 변경으로 고쳤다. 모니터 작업 영역·혼합 배율·음수 좌표·모니터 제거를 계산하고 마지막 상대 위치를 저장한다. 두 OS 실제 이동 시험은 남았다.
- 모델 가져오기는 임시 폴더의 검사 자산으로 먼저 로드하고, 감정·입 모양을 미리 본 뒤 사용을 확정한다. 취소·Core 실패·저장 실패 복원 및 지연 메타데이터 응답을 검사했다. 브라우저에서는 Haru 미리보기·샘플 재생·취소 후 Mao 복원과 Kei 확정을 확인했다.
- 선택 표정·물리·포즈·MotionSync의 손상 또는 실제 ID 불일치를 기능 경고로 처리한다. 위험 경로·필수 자산 실패는 계속 거부한다. 매핑 변경 후 기능 지원 표시를 즉시 갱신한다.
- 두 창 모두 숨김·최소화되면 수동·자동 관찰을 모두 취소한다. 입력 상태 미확인·입력 중에는 자동 관찰만 취소한다. 허용 앱의 활성 창 변경은 시각·출처·식별자·범위를 담은 OS 사건으로 전달하고 화면 분석과 같은 침묵·중복 정책을 적용한다. 숨김 렌더러의 rAF와 30 Hz 커서 IPC를 중단한다.
- 모델별 실제 Core 파라미터 ID·최소/최대/기본값과 표정 목록을 SQLite 스키마 3에 저장한다. 캐시로 이후 Core 검사를 생략하지 않는다.
- 전체 Rust 검사에서 발견한 합성 HTTP 서버의 nonblocking 소켓 상속을 수정했다. 연결 후 헤더 도착 지연 회귀를 추가했고 이후 수동 관찰 경계를 포함한 최종 전체 검사 79개가 통과했다.
- ImageBitmap의 알파 사전 곱셈과 Cubism 블렌딩 계약을 일치시켜 Mao 얼굴/몸의 흰 사각형을 제거했다. 브라우저에서 수정 결과를 확인했다.
- MotionSync Core를 모듈보다 먼저 읽고 `MotionSyncOption`을 전달했다. CRI가 소비하지 않은 PCM tail을 다음 분석에 보존한다.
- 폼의 `name="id"`가 `form.id`를 가리는 브라우저 동작으로 모델교체/기억저장이 분기되지 않던 문제를 `getAttribute('id')`로 수정했다. Haru/Kei 실제 교체를 확인했다.
- 새 모델은 Core 로딩 성공 후 인격/기억 교체를 확정한다. 손상 모델의 로딩 실패가 이전 기억을 먼저 지우지 않게 했다.
- 늦은 디코드·마이크 권한·STT/TTS 응답은 취소된 발화/모델을 다시 시작하지 못하도록 검사한다. 미리보기 감정과 실제 음성의 상태를 분리했다.

사용자 확인 우선순위는 (1) 앱 실행·투명 캐릭터, (2) 다른 앱 위에서 커서 추적·여백 클릭 통과·드래그, (3) 캐릭터 화면 한국어 샘플 재생·중지, (4) 필요한 AI 제공자를 설정한 직접 대화다. 관찰은 기본으로 꺼져 있고 사용자가 범위와 권한을 지정해야 한다.

Windows 제한: Win32 입력 데스크톱 판별만으로 RDP 연결 해제를 보장하지 않는다. 원격 세션까지 검증한 것으로 표시하지 않으며, 향후 WTS 상태 검사와 실기 시험이 필요하다.

클릭 영역은 실제 모델 삼각형·UV·텍스처 알파·일반/반전 마스크와 그리기 순서·신형 알파 합성·중첩 offscreen을 계산한다. 이미지 로딩 시 긴 변 최대 1024픽셀의 CPU 알파 캐시를 만들고 매 프레임 GPU 읽기는 하지 않는다. Haru·Mao·Ren의 8개 상태, 26,800개 표본에서 명확한 투명·불투명 영역의 오판이 0이었고, Ren 재로딩의 삭제된 framebuffer 캐시도 수정했다. [측정 근거와 경계 오차](model-hit-testing.md)를 확인할 수 있다. 네이티브 클릭 통과는 실제 확인해야 한다.
