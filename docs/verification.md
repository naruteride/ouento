# MVP 검증 기록

2026-09-22 최초 기록. 근거는 루트 기획서와 AGENTS.md다. **코드 구현, 자동 검증, 두 OS 배포 앱 검증, 사용자 알파는 서로 다른 단계**이며 하나의 완료로 합치지 않는다. 아래 미검증 항목은 통과한 것으로 간주하지 않는다. 렌더러·Tauri·설정 화면은 연결했으며, 아래 자동 검증과 브라우저 확인을 수행했다. 네이티브 실기 검증은 아직 완료되지 않았다.

## 현재 확인한 환경과 결과

### 2026-09-26 재실행 설정 복원·개발 앱 서명 수정

- 재실행 시 모든 관찰 모드·동의를 무조건 지우던 코드를 제거했다. 유효하게 저장한 전체 모니터·허용 앱 선택과 동의는 유지한다. 개별 창 모드는 OS ID 재사용을 막기 위해 꺼짐으로 전환하고 재선택을 요구한다. 이때 일반 설정 저장은 계속 가능하다. 사용자가 관찰을 중지한 상태와 불완전한 동의는 자동으로 활성화하지 않는다.
- Rust 단위 85개·loopback HTTP 18개·Clippy 전체 타깃 경고 0으로 통과했다. Node 73개·컨트롤러 61개·TypeScript 검사도 통과했다.
- 수정 전 앱의 `codesign -d -r-` 결과는 `linker-signed` ad-hoc, `Info.plist=not bound`, `Sealed Resources=none`, `designated => cdhash ...`였다. UI에서 현재 프로세스의 화면 접근은 미적용, 입력 활동도 확인 불가였다. `CGPreflightScreenCaptureAccess`를 항상 최신으로 호출하므로 허용 스위치와 실제 실행 파일 식별 불일치를 표시 캐시로 취급하지 않았다. Apple의 [코드 식별과 권한 추적 설명](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)을 근거로 서명 절차를 수정한다.
- 전용 로컬 개발 인증서를 로그인 키체인에 만들고 같은 인증서 재사용을 확인했다. 시스템 신뢰 설정은 변경하지 않았다. 수정 `.app`은 인증서 leaf 지문과 `com.ouento.desktop`을 고정하여 서명했으며, 샌드박스 밖의 `codesign --verify --deep --strict --verbose=2`가 `valid on disk`와 `satisfies its Designated Requirement`를 반환했다. 공개 지문 마커로 인증서가 안 보일 때 미서명 빌드 성공 처리를 차단한다. 관련 도구 모의 검사 13개·Prettier·diff 검사가 통과했다.
- 사용자 프로필을 직접 고치지 않고, 기존 앱에서 사용자가 적용한 전체 모니터 모드·두 동의가 수정 앱 재실행 후 모두 유지됨을 네이티브 UI에서 확인했다. 시스템 설정의 기존 Ouento 허용 스위치는 on이었으며, 새 서명으로 다시 적용하는 과정에서 Touch ID 인증이 요구되어 사용자 인증을 기다리고 있다. 권한 재적용 후 재실행 검증은 아직 미완료다. 화면 캡처·외부 AI 전송은 실행하지 않았다.
- 서명된 개발 앱: `src-tauri/target/debug/bundle/macos/Ouento.app`, 실행 파일 SHA-256 `6a1c77bb1e0df157e4ed37dcccda7cabe8c67953638406313f1abc892d4bf725`. 첫 실행의 기존 WebGL 초기화 오류는 다시 나타났고, 최종 재실행에서의 확인은 남아 있다. Windows 실기는 미실시다.

### 2026-09-26 현재 모니터 전체 보기 추가

- 사용자 선택에 따라 `currentScreen`을 추가했다. 마우스가 있는 모니터를 따르며 개별 창·앱 선택을 요구하지 않는다. 기존 화면 전송 동의 외에 `screenConsent`가 필요하고 관찰 중지·재시작 때 두 동의를 해제한다. N분마다 말하는 옵션은 추가하지 않았다.
- 전체 화면은 다른 창·알림·바탕화면을 포함한다. 자체 앱을 캡처에서 제외하고, 제목 없는 창도 포함한 OS 목록에서 민감 앱이 모니터와 겹치거나 앱 식별에 실패하면 분석을 쉰다. 캡처 전후의 모니터·창 구성과 응답·TTS·재생까지 관찰 범위를 재확인한다. 모든 민감 콘텐츠를 자동으로 판별한다는 보장은 아니다.
- Node 회귀 73개, 컨트롤러 61개, TypeScript 및 Prettier 검사 통과. 실제 브라우저 `tests/browser/ui-stability.html` 25개 모두 통과: 새 모드의 개별 창 선택 생략, 별도 동의 필수, 500ms 상태 갱신 중 모드·동의 초안 유지와 기존 DOM 안정성을 확인했다.
- Rust 단위 82개·loopback HTTP 18개, Clippy 전체 타깃 경고 0으로 통과했다. 동의 철회·관찰 중지·재시작, 모니터와 해상도 변경 후 늦은 응답/음성 폐기, 전송 전 검증 실패 시 HTTP 없음, 응답 후 검증 실패 시 대화 기록 오염 없음, 제목 없는 민감 창의 화면 교차와 이미지 행 패딩 변환을 검사했다. Windows 소스의 호스트 메타데이터 타입 검사도 통과했으나 Windows 링크·실행 검증은 아니다.
- `npm run tauri -- build --debug --bundles app` 성공. 새 macOS 앱의 Mao LIVE, 전체 모니터 선택 항목, 추가 전송 동의의 초기 해제 상태와 개별 창 선택 생략을 네이티브 UI에서 확인했다. 동의를 켜거나 관찰 범위를 저장하지 않았다. 기존 앱에서는 화면 접근 허용·입력 감지 불가였으며, 새 빌드 재실행 후에는 화면 접근도 미적용으로 표시됐다. 개발용 ad-hoc 서명 변경에 따른 권한 재적용 문제는 남아 있고 권한 설정을 변경하지 않았다.
- 산출물: `src-tauri/target/debug/bundle/macos/Ouento.app`, 실행 파일 SHA-256 `461d56834563ba0e02c95ea710f15f6bf18f492c3033a5d05dacb374b79ec62d`. 앱 최소 macOS 12.3, 전체 모니터 모드 macOS 14 이상. 최저 OS 실행은 미검증이다.
- 사용자 화면의 전체 캡처·외부 AI 전송, 실제 다중 모니터 전환·자체 창 제외·민감 앱 겹침의 픽셀 검증, Windows 빌드·실기는 수행하지 않았다. 자동 검증에는 합성 자료만 사용했다.

### 2026-09-26 주기 갱신과 화면 권한 수정

- 500ms 활동 이벤트마다 페이지의 `innerHTML`을 교체하고 `scrollTop`을 복원하던 경로를 제거했다. 기존 DOM을 유지하며 변경된 값만 반영한다. 상태 갱신 중 열린 select·선택 텍스트·미저장 초안·스크롤을 유지하고, 명시적인 매핑 취소와 페이지 이동에서는 입력값/읽던 대화 위치를 복구한다.
- 실제 브라우저 `tests/browser/ui-stability.html`의 21개 검사 모두 통과: 500ms 반복 상태 변경 중 select/option/폼 identity·포커스·초안·본문 Range 유지, main/chat의 scrollTop 대입 0회, 과거 대화 읽기와 페이지 재진입, 매핑 취소, 권한 표시 변경을 확인했다. OS 고유 바운스 애니메이션의 시각 품질을 자동 검사가 대신하지 않는다.
- `npm test` 63개, `npm run test:controllers` 61개(권한 갱신 13개 포함), Rust `platform::tests` 4개 통과. 변경 JS 포맷·Rust 포맷·`git diff --check` 통과. `npm run tauri -- build --debug --bundles app`로 프런트엔드 정적 검사와 macOS 앱 빌드 성공.
- 네이티브 앱에서 ‘프레임 속도’와 ‘함께 볼 창’ 팝업이 각각 500ms보다 긴 간격의 두 관측 사이에 유지됨을 확인했다. CUA 좌표 스크롤/드래그는 `noWindowsAvailable`로 실패해 macOS 트랙패드 바운스·본문 마우스 드래그의 최종 실기는 별도 확인이 필요하다. 빌드 직후 첫 실행에서 그래픽 초기화 오류가 나타났으나 같은 앱을 다시 실행해 Mao의 LIVE 상태와 오류 해소를 확인했다. 이 초기 실행 현상은 주기 갱신 회귀와 구분한다.
- 권한 조회를 초기 snapshot에서 분리해 앱 포커스/표시 복귀·창 목록 새로고침에 최신 상태를 읽는다. 요청 전 진행 중이던 조회의 오래된 결과로 권한을 덮어쓰지 않는다. 거부로 단정하던 문구를 현재 프로세스에 적용되지 않은 상태와 재실행 안내로 수정했다.
- 시스템 설정의 Ouento 화면 기록 스위치는 on이었지만 현재 프로세스의 preflight는 false였다. 사용자 승인과 직접 Touch ID 인증 후 off/on·재실행으로는 해결되지 않았다. 이전 항목을 제거하고 아래 최종 앱 경로를 다시 추가한 뒤 앱에서 ‘화면 접근이 허용되어 있어요’를 확인했다. 같은 실행 파일을 한 번 더 재실행한 뒤에도 허용 상태가 유지됐다. 실제 사용자 화면 캡처·외부 AI 호출은 하지 않았다.
- 현재 앱은 ad-hoc 개발 서명이며 유효한 개발 서명 인증서는 설치되어 있지 않다. 이후 재빌드 시 OS 허용 항목 재등록이 다시 필요할 수 있다. 빌드 간 권한 유지는 동일한 Apple 개발 서명 구성으로 별도 해결해야 한다. [Apple DTS 근거](https://developer.apple.com/forums/thread/819406).

### 2026-09-23 화면 구석 배치 수정

- 드래그 종료·2초 주기 검사·재실행 시 화면 안으로 강제 이동하던 제한을 제거했다. 화면 밖 좌표는 위치 파일 버전 2로 저장하고 기존 버전 1도 읽는다. 모니터 제거 복구와 Retina 크기 반올림 회귀를 포함한 `cargo test --manifest-path src-tauri/Cargo.toml --locked desktop::tests` 11개가 통과했다.
- 사용자가 트레이 또는 설정 창의 ‘캐릭터 표시’를 직접 누르면 우측 하단으로 되찾는다. 앱 시작 시 자동 표시는 저장 위치를 유지한다. `node scripts/check-controller.mjs` 18개 시나리오와 `npm run tauri -- build --debug --bundles app`가 통과했다.
- 새 macOS 앱에서 CUA로 Mao 렌더링, 설정 창의 표시 버튼, 화면 밖에 저장된 위치의 명시적 복구를 확인했다. 복구 후 위치 파일의 `(horizontal, vertical) = (1, 1)`이 67초 뒤에도 그대로였다. 캐릭터 창은 포커스를 받지 않는 dialog이며 CUA 좌표 드래그가 `noWindowsAvailable`로 실패하므로, 실제 구석까지 드래그·재실행하는 최종 GUI 검증은 **미완료**다. 권한으로 앱 읽기와 일반 창 버튼 조작은 가능해졌으며, 현재 실패를 권한 거부로 기록하지 않는다. Windows 실기는 이번에도 수행하지 않았다.

## 실제 브라우저 반복 검사

개발용 `tests/browser/model-soak.html`에서 공식 Mao/Haru/Kei를 50회 교체했다. 실제 Core·WebGL2·MotionSync·Web Audio API를 감싸 생성/해제를 세며 원래 호출을 실행한다. 최종 결과는 [측정 요약 JSON](browser-model-soak-2026-09-22.json)에 보관했다.

- 26.119초 동안 기본 50회 교체, 지연된 물리 자산 요청 중 교체, `WEBGL_lose_context` 손실·복구를 완료했다. 최종 오류 배열은 비어 있고 복구 후 실제 GPU draw가 재개됐다.
- 최종 해제 후 Core Model/Moc·Texture·Buffer·Framebuffer·Program·Shader의 추적 핸들은 모두 0, MotionSync 분석기·예약 rAF도 0, AudioContext는 closed다. 반복 중 각 모델의 자원 수가 증가하지 않는지도 검사했다.
- Haru, CSS 360×500, DPR 2, Chrome 152 기반 브라우저, 각 2.2초 표본에서 30 설정은 30.02 FPS(간격 중간값 33.3ms/p95 50ms), 60 설정은 55.42 FPS(16.7ms/32.5ms)였다. 브라우저 rAF는 60Hz였고 최종 측정 중 Tauri debug 빌드를 병행했다. 안정된 60 FPS를 입증한 결과가 아니다.
- 정지 중 250ms 동안 draw/rAF 0, 재개 후 루프 1개를 확인했다. JS heap 단일 표본은 GC·SDK 전역을 포함하므로 메모리 누수 판단에 사용하지 않는다. 네이티브 프로세스 전체 RAM/GPU·전력·8시간 측정은 여전히 미실시다.

이 검사에서 미완료 모델의 Core 해제, GL별 셰이더 캐시 해제·재생성, MotionSync 부분 생성 실패 정리, rAF 예약 위상 보존을 보완했다. 그래픽 연결 손실 이벤트 직전/그리기 중 예외도 보완해 재검사했다. SDK 수정은 원본/수정 SHA를 고정한 `assets:setup` 패치로 재현한다.

## 실제 브라우저 몸짓 검사

2026-09-22 `tests/browser/gesture-check.html`에서 Mao·Haru·Kei의 끄덕임·기울임·작은 상체 리듬·고개 돌림을 각각 3초 동안 재생했다. 실제 SDK drawModel 직후 전체 파라미터의 유한 값·범위, 몸짓 축과 같은 시각의 기본 동작 차이, 모델 행렬, GL 오류를 확인했다. [측정 요약](gesture-check-2026-09-22.json)의 12개 경우 모두 오류 0, 복귀 오차 0, 모델 전체 위치 고정이었다. 각 경우의 실제 프레임 5장을 비교했고 전신 점프·창 이동을 추가하지 않았다. 커서·깜박임 고정 및 감정 강도 0의 진단이므로 감정·음성 합성의 자연스러움은 별도 확인이 필요하다.

몸짓의 앱 실행 시간과 무관한 시작·단발 재생, 발화 중 복귀, 없는 축 건너뛰기, 강도 0, 실제 파라미터 범위는 Node Core 회귀로도 확인했다. Rust에서는 프리셋별 표정/몸짓 독립 배율과 같은 합격 장면 미리보기의 일치를 검사했다.

## 이번 통합에서 수정한 문제

- 기억 입력과 채팅 입력의 길이를 Rust와 동일한 Unicode 기준으로 제한한다. 기억 저장은 실제 쓰기 성공 후에만 작성창을 닫으며 실패 시 초안을 보존한다. 저장 성공 후 목록 조회 실패는 재저장과 구분하여 중복 삽입을 막는다. 실제 UI 메서드 8개와 컨트롤러 4개 회귀를 추가했다. `tests/browser/forms-check.html`의 실제 Web Component에서 한글 1,001자 기억/4,001자 대화 차단·입력 유지, 저장 실패 후 초안 유지, 성공 후 닫힘·목록 갱신, 이모지 4,000자 대화 제출을 확인했다. 브라우저의 저장 응답은 합성 대체이며 실제 SQLite 저장 검증은 Rust 검사와 구분한다.

- 수동 화면 분석은 자동 관찰의 입력·침묵 제한과 구분한다. 캡처 준비 전에 취소 세대를 고정하고, 응답에는 원래 네이티브 대상을 연결해 TTS 대기·완료·재생 중 창 변경과 권한 철회를 검사한다. 이전 발화의 늦은 취소 이벤트는 같은 ID의 관찰만 중지한다. 합성 HTTP/OS 자료와 UI/오디오 회귀로 검증했으며 실제 권한 철회는 실기 검증이 남았다.
- 전역 표시 크기가 고정 창 안의 모델만 확대하던 것을 네이티브 창 크기 변경으로 고쳤다. 모니터 작업 영역·혼합 배율·음수 좌표·모니터 제거를 계산하고 마지막 상대 위치를 저장한다. 두 OS 실제 이동 시험은 남았다.
- 모델 가져오기는 임시 폴더의 검사 자산으로 먼저 로드하고, 감정·입 모양을 미리 본 뒤 사용을 확정한다. 취소·Core 실패·저장 실패 복원 및 지연 메타데이터 응답을 검사했다. 브라우저에서는 Haru 미리보기·샘플 재생·취소 후 Mao 복원과 Kei 확정을 확인했다.
- 선택 표정·물리·포즈·MotionSync의 손상 또는 실제 ID 불일치를 기능 경고로 처리한다. 위험 경로·필수 자산 실패는 계속 거부한다. 매핑 변경 후 기능 지원 표시를 즉시 갱신한다.
- 두 창 모두 숨김·최소화되면 수동·자동 관찰을 모두 취소한다. 실제 입력 중에는 자동 관찰만 취소한다. 입력 미확인은 자동 관찰을 취소하지 않는다. 허용 앱의 활성 창 변경은 시각·출처·식별자·범위를 담은 OS 사건으로 전달하고 화면 분석과 같은 침묵·중복 정책을 적용한다. 숨김 렌더러의 rAF와 30 Hz 커서 IPC를 중단한다.
- 모델별 실제 Core 파라미터 ID·최소/최대/기본값과 표정 목록을 SQLite 스키마 3에 저장한다. 캐시로 이후 Core 검사를 생략하지 않는다.
- 전체 Rust 검사에서 발견한 합성 HTTP 서버의 nonblocking 소켓 상속을 수정했다. 연결 후 헤더 도착 지연 회귀를 추가했고 이후 수동 관찰·성격 강도 경계를 포함한 전체 검사 84개가 통과했다.
- ImageBitmap의 알파 사전 곱셈과 Cubism 블렌딩 계약을 일치시켜 Mao 얼굴/몸의 흰 사각형을 제거했다. 브라우저에서 수정 결과를 확인했다.
- MotionSync Core를 모듈보다 먼저 읽고 `MotionSyncOption`을 전달했다. CRI가 소비하지 않은 PCM tail을 다음 분석에 보존한다.
- 폼의 `name="id"`가 `form.id`를 가리는 브라우저 동작으로 모델교체/기억저장이 분기되지 않던 문제를 `getAttribute('id')`로 수정했다. Haru/Kei 실제 교체를 확인했다.
- 새 모델은 Core 로딩 성공 후 인격/기억 교체를 확정한다. 손상 모델의 로딩 실패가 이전 기억을 먼저 지우지 않게 했다.
- 늦은 디코드·마이크 권한·STT/TTS 응답은 취소된 발화/모델을 다시 시작하지 못하도록 검사한다. 미리보기 감정과 실제 음성의 상태를 분리했다.
- `smallBounce`·`lookAway`가 실제 고개·상체 축을 움직이지 않던 누락을 수정했다. 몸짓을 반응 시작 기준의 단발 동작으로 바꾸고 프리셋의 동작 크기를 표정과 따로 적용한다. 합격 화면의 표정 강도가 두 번 줄어들던 문제와 브라우저/네이티브 미리보기 차이도 수정했다.
- Windows 기본 마우스 버튼을 오른쪽으로 바꾼 경우에도 실제 기본 버튼 상태를 읽도록 수정했다. 호스트 메타데이터 타입 검사는 통과했으며 Windows 실기 드래그 검증은 남아 있다.

사용자 확인 우선순위는 (1) 앱 실행·투명 캐릭터, (2) 다른 앱 위에서 커서 추적·여백 클릭 통과·드래그, (3) 캐릭터 화면 한국어 샘플 재생·중지, (4) 필요한 AI 제공자를 설정한 직접 대화다. 관찰은 기본으로 꺼져 있고 사용자가 범위와 권한을 지정해야 한다.

Windows 제한: Win32 입력 데스크톱 판별만으로 RDP 연결 해제를 보장하지 않는다. 원격 세션까지 검증한 것으로 표시하지 않으며, 향후 WTS 상태 검사와 실기 시험이 필요하다.

클릭 영역은 실제 모델 삼각형·UV·텍스처 알파·일반/반전 마스크와 그리기 순서·신형 알파 합성·중첩 offscreen을 계산한다. 이미지 로딩 시 긴 변 최대 1024픽셀의 CPU 알파 캐시를 만들고 매 프레임 GPU 읽기는 하지 않는다. Haru·Mao·Ren의 8개 상태, 26,800개 표본에서 명확한 투명·불투명 영역의 오판이 0이었고, Ren 재로딩의 삭제된 framebuffer 캐시도 수정했다. [측정 근거와 경계 오차](model-hit-testing.md)를 확인할 수 있다. macOS 클릭 통과는 위 사용자 확인을 기록했으며 Windows 및 상세 배율 조건은 별도 확인해야 한다.
